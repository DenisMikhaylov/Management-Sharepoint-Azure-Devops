# Лабораторная работа: Настройка проектов, команд и прав доступа в Azure DevOps

**Цель работы:** получить практические навыки создания проектов на основе различных процессов (Agile, Scrum, CMMI), создания команд внутри проектов и настройки гранулярных прав доступа к рабочим элементам на основе областей (Area Paths).

**Предварительные требования:**
- Учётная запись Azure DevOps с правами **Project Collection Administrator** (или правами на создание проектов и управление безопасностью на уровне проекта).
- Доступ к веб-порталу `https://dev.azure.com/<Ваша_Организация>`.

---

## Теоретическая справка

Каждый проект в Azure DevOps основан на одном из встроенных процессов, который определяет типы рабочих элементов, их состояния и правила. Основные процессы: **Agile**, **Basic**, **Scrum** и **CMMI**. В одном проекте может быть создано несколько команд. Каждая команда автоматически получает собственную группу безопасности и набор Agile-инструментов (Backlogs, Boards, Sprints).

Области (Area Paths) служат для группировки рабочих элементов по командам, продуктам или функциональным направлениям. **Ключевой механизм безопасности:** права доступа к рабочим элементам можно назначать на уровне Area Path. Если команде запретить доступ к чужой области, её участники не смогут видеть и редактировать рабочие элементы, назначенные на эту область.

## Ход работы

### Часть 1. Создание проектов

**Задача:** создать три проекта с именами `Lab-Agile`, `Lab-Scrum` и `Lab-CMMI`, каждый на основе соответствующего процесса.

**Шаги:**

1.  Войдите в свою организацию Azure DevOps.
2.  Нажмите **New project** (Создать проект).
3.  Заполните поля:
    - **Project name:** `Lab-Agile`
    - **Description:** Проект для изучения процесса Agile
    - **Visibility:** Private
    - **Version control:** Git
    - **Work item process:** **Agile**
4.  Нажмите **Create**.
5.  Повторите шаги 2–4 для создания проекта `Lab-Scrum` (выберите процесс **Scrum**) и `Lab-CMMI` (выберите процесс **CMMI**).

> **Примечание:** Каждый проект автоматически получает команду по умолчанию с именем проекта и корневую область (Area Path), совпадающую с именем проекта.

---

### Часть 2. Создание команд в каждом проекте

**Задача:** в каждом из трёх проектов создать по три команды: `Team-Alpha`, `Team-Beta`, `Team-Gamma`.

**Шаги (для каждого проекта):**

1.  Откройте проект (например, `Lab-Agile`).
2.  Перейдите в **Project settings** (Параметры проекта) → **Teams** (Команды).
3.  Нажмите **New team** (Новая команда).
4.  Введите имя: `Team-Alpha`, добавьте описание по желанию.
5.  Нажмите **Create team**.
6.  Повторите шаги 3–5 для создания команд `Team-Beta` и `Team-Gamma`.
7.  **Важно:** после создания каждой команды выберите её, перейдите на вкладку **Iterations and areas** (Итерации и области) и **назначьте команде область по умолчанию** (см. Часть 3), иначе инструменты команды (доски, бэклоги) не будут работать.

> **Пояснение:** При создании команды Azure DevOps автоматически создаёт группу безопасности с тем же именем. Эта группа будет использоваться для назначения прав доступа к Area Paths.

---

### Часть 3. Настройка областей (Area Paths)

**Задача:** создать отдельные области для каждой команды и назначить их соответствующим командам.

**Шаги (для каждого проекта):**

1.  Перейдите в **Project settings** → **Project configuration** → **Areas** (Области).
2.  Убедитесь, что корневая область (имя проекта) существует.
3.  Создайте три дочерние области под корневой:
    - `Lab-Agile\Team-Alpha`
    - `Lab-Agile\Team-Beta`
    - `Lab-Agile\Team-Gamma`
    
    Для этого нажмите на корневую область, затем **New child** (Создать дочернюю), введите имя и сохраните.
4.  Вернитесь в **Project settings** → **Teams**.
5.  Выберите `Team-Alpha`, перейдите на вкладку **Iterations and areas**.
6.  В разделе **Areas** нажмите **Add area** и выберите `Lab-Agile\Team-Alpha`. Нажмите **Save and close**.
7.  Повторите шаги 5–6 для `Team-Beta` (область `Team-Beta`) и `Team-Gamma` (область `Team-Gamma`).
8.  Повторите всю процедуру для проектов `Lab-Scrum` и `Lab-CMMI`, создав соответствующие области с префиксом имени проекта.

> **Результат:** каждая команда «привязана» к своей области. Рабочие элементы, созданные в бэклоге команды, автоматически получают её Area Path.

---

### Часть 4. Настройка прав доступа к рабочим элементам на основе Area Path

**Задача:** настроить безопасность так, чтобы каждая команда могла видеть и редактировать **только** рабочие элементы своей области, и **не могла** видеть рабочие элементы других команд.

**Шаги (для каждого проекта):**

1.  Перейдите в **Project settings** → **Project configuration** → **Areas**.
2.  Вы увидите три дочерние области, назначенные командам.
3.  Нажмите на область `Team-Alpha` (или нажмите на три точки справа → **Security**).
4.  Откроется окно безопасности для этой области. Вы увидите список групп безопасности, включая группы команд (`Team-Alpha`, `Team-Beta`, `Team-Gamma`).
5.  Настройте права для **чужих** команд:
    - Для группы `Team-Beta` установите для разрешения **View work items in this node** (Просмотр рабочих элементов в этом узле) значение **Deny** (Запретить).
    - Для группы `Team-Gamma` сделайте то же самое.
    - Для группы `Team-Alpha` оставьте **Allow** (Разрешить) или **Not set** (по умолчанию наследуется).
6.  Повторите шаги 3–5 для области `Team-Beta`: запретите доступ для `Team-Alpha` и `Team-Gamma`.
7.  Повторите для области `Team-Gamma`: запретите доступ для `Team-Alpha` и `Team-Beta`.
8.  Повторите всю процедуру для проектов `Lab-Scrum` и `Lab-CMMI`.

> **Важно:** разрешение **Deny** имеет приоритет над **Allow**. Устанавливая Deny на просмотр рабочих элементов в чужой области, вы полностью скрываете эти рабочие элементы от участников команды.

---

### Часть 5. Проверка результата

**Задача:** убедиться, что настройки безопасности работают корректно.

**Шаги:**

1.  Добавьте тестового пользователя (или используйте второго себя, если есть возможность) в команду `Team-Alpha` проекта `Lab-Agile`. Для этого: **Project settings** → **Teams** → `Team-Alpha` → **Add** (в разделе Members).
2.  Войдите в Azure DevOps под этим пользователем.
3.  Создайте рабочий элемент (например, User Story) в бэклоге команды `Team-Alpha`. Убедитесь, что он отображается.
4.  Попробуйте создать рабочий элемент, явно указав Area Path `Lab-Agile\Team-Beta`. Убедитесь, что элемент **не создаётся** или **не отображается** в представлениях команды `Team-Alpha`.
5.  Перейдите на доску команды `Team-Beta` (под тем же пользователем). Убедитесь, что рабочие элементы этой команды **не видны**.
6.  Повторите проверку для других проектов и команд.
