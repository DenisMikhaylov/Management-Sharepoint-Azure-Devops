# Лабораторная работа: Создание системы управления инцидентами в SharePoint Online и Power Apps

## Цель работы

Научиться создавать связанные списки SharePoint Online для построения логики управления инцидентами, а также создавать и настраивать форму ввода данных в Power Apps для оптимизации процесса регистрации инцидентов.

## Теоретическая часть

### Что такое списки SharePoint и зачем они нужны

SharePoint списки — это структурированные контейнеры данных, которые позволяют хранить, организовывать и управлять информацией. Они представляют собой таблицы, где каждая строка — это запись, а каждый столбец — это поле с определённым типом данных. Списки SharePoint широко используются для создания трекеров задач, реестров инцидентов, баз контактов и других бизнес-приложений.

### Связи между списками: столбец Lookup

Столбец типа **Lookup** (подстановка) — это специальный тип столбца, который извлекает значения из другого списка (исходного списка) и отображает их в виде выпадающего списка в текущем списке (целевом списке). Это создаёт простую связь между списками, позволяя повторно использовать мастер-данные, такие как категории, приоритеты, статусы или ответственные сотрудники.

**Важно:** Lookup-столбцы могут ссылаться только на определённые типы столбцов исходного списка: однострочный текст, число, дата и время. Такие типы, как «Выбор» (Choice), «Человек или группа», «Многострочный текст», не могут быть использованы в качестве основного поля подстановки.

### Интеграция SharePoint с Power Apps

Power Apps позволяет настраивать формы SharePoint-списков, заменяя стандартные формы создания и редактирования на кастомизированные. При интеграции списка в Power Apps создаётся форма, которая может создавать, отображать и редактировать элементы списка. В основе этой формы лежит элемент управления **SharePointIntegration**, который передаёт действия пользователя между SharePoint и Power Apps.

## Архитектура решения

В данной лабораторной работе мы создадим три связанных списка SharePoint:

| Список | Назначение | Связи |
|--------|-----------|-------|
| **Категории инцидентов** | Справочник категорий (например, «Аппаратное обеспечение», «Программное обеспечение», «Сеть») | Исходный список для подстановки |
| **Приоритеты** | Справочник уровней приоритета (например, «Критический», «Высокий», «Средний», «Низкий») | Исходный список для подстановки |
| **Инциденты** | Основной список для регистрации инцидентов | Целевой список с Lookup-столбцами на два справочника |

Логика связи: при регистрации инцидента пользователь выбирает категорию и приоритет из выпадающих списков, которые заполняются данными из соответствующих справочников. Это обеспечивает целостность данных и исключает ручной ввод повторяющейся информации.

## Часть 1. Создание справочных списков SharePoint

### Шаг 1.1. Создание списка «Категории инцидентов»

1. Откройте SharePoint Online в браузере и перейдите на сайт, где будет размещено решение. Если сайта нет, создайте новый сайт группы.

2. На левой панели навигации нажмите **«Содержимое сайта»** (Site Contents).

3. Нажмите **«Создать»** → **«Список»** (New → List).

4. В окне создания выберите **«Пустой список»** (Blank list).

5. Введите имя списка: `Категории инцидентов`. Описание можно оставить пустым или указать: «Справочник категорий для классификации инцидентов».

6. Нажмите **«Создать»** (Create).

7. После создания списка откройте его. По умолчанию в списке есть только столбец **«Название»** (Title), который мы будем использовать как название категории.

8. Добавьте дополнительные столбцы:
   - Нажмите **«+ Добавить столбец»** (+ Add column).
   - Выберите тип **«Однострочный текст»** (Single line of text).
   - Введите имя: `Описание категории`.
   - Нажмите **«Сохранить»** (Save).

9. Заполните список значениями. Нажмите **«Добавить элемент»** (New) и последовательно внесите категории:

| Название | Описание категории |
|----------|-------------------|
| Аппаратное обеспечение | Проблемы с компьютерами, серверами, периферией |
| Программное обеспечение | Ошибки в приложениях, сбои ПО |
| Сеть | Проблемы с подключением, DNS, VPN |
| Безопасность | Инциденты ИБ, подозрительная активность |
| Доступ | Проблемы с правами, учётными записями |

**Пояснение:** Этот список будет выступать в роли исходного списка для Lookup-столбца в основном списке инцидентов. Значения из этого списка будут автоматически предлагаться пользователю при выборе категории инцидента.

### Шаг 1.2. Создание списка «Приоритеты»

1. Вернитесь в **«Содержимое сайта»** и нажмите **«Создать»** → **«Список»** → **«Пустой список»**.

2. Введите имя: `Приоритеты`. Нажмите **«Создать»**.

3. Добавьте столбец **«Уровень»** типа **«Число»** (Number):
   - Нажмите **«+ Добавить столбец»** → **«Число»**.
   - Имя: `Уровень`. Этот столбец будет содержать числовое значение приоритета (1 — наивысший).

4. Заполните список:

| Название | Уровень |
|----------|---------|
| Критический | 1 |
| Высокий | 2 |
| Средний | 3 |
| Низкий | 4 |

**Пояснение:** Числовое поле «Уровень» позволит в дальнейшем сортировать инциденты по важности и использовать числовые значения в формулах Power Apps.

### Шаг 1.3. Создание основного списка «Инциденты»

1. Создайте третий список: **«Содержимое сайта»** → **«Создать»** → **«Список»** → **«Пустой список»**.

2. Имя: `Инциденты`.

3. Добавьте следующие столбцы:

| Имя столбца | Тип | Настройки |
|-------------|-----|-----------|
| `Описание` | Многострочный текст | Без ограничений |
| `Дата регистрации` | Дата и время | Формат: только дата |
| `Статус` | Выбор | Варианты: Новый, В работе, Решён, Закрыт. Значение по умолчанию: Новый |
| `Ответственный` | Человек или группа | Разрешить выбор: Люди и группы |
| `Категория` | Lookup | См. шаг 1.4 |
| `Приоритет` | Lookup | См. шаг 1.4 |

### Шаг 1.4. Создание Lookup-столбцов (связей между списками)

Это ключевой этап, который создаёт связи между списками.

**Создание Lookup-столбца «Категория»:**

1. В списке **«Инциденты»** нажмите **«+ Добавить столбец»** → выберите **«Подстановка»** (Lookup) → **«Далее»**.

2. Заполните настройки:
   - **Имя столбца:** `Категория`
   - **Описание:** «Категория инцидента (из справочника)»
   - **Выберите список в качестве источника:** выберите `Категории инцидентов`
   - **Выберите столбец из списка выше:** выберите `Название`

3. Разверните **«Дополнительные параметры»** (More options) и в разделе **«Дополнительные столбцы»** (Additional columns) отметьте `Описание категории`. Это позволит автоматически подтягивать описание категории в карточку инцидента.

4. Нажмите **«Сохранить»**.

**Создание Lookup-столбца «Приоритет»:**

1. Аналогично нажмите **«+ Добавить столбец»** → **«Подстановка»** → **«Далее»**.

2. Настройки:
   - **Имя столбца:** `Приоритет`
   - **Выберите список в качестве источника:** `Приоритеты`
   - **Выберите столбец из списка выше:** `Название`
   - В дополнительных столбцах отметьте `Уровень`

3. Нажмите **«Сохранить»**.

**Пояснение:** Теперь при создании нового инцидента в списке «Инциденты» поля «Категория» и «Приоритет» будут представлять собой выпадающие списки, заполненные значениями из справочников. Это гарантирует, что пользователь не введёт произвольное значение, а выберет из предопределённых.

### Шаг 1.5. Проверка работы связей

1. В списке **«Инциденты»** нажмите **«Добавить элемент»**.

2. Убедитесь, что в поле **«Категория»** выпадающий список содержит категории из справочника.

3. Выберите категорию «Сеть» и приоритет «Высокий». Заполните остальные поля.

4. Сохраните элемент.

5. Вернитесь в список **«Категории инцидентов»** и измените название одной из категорий. Убедитесь, что изменения отразились в связанном инциденте.

## Часть 2. Создание формы в Power Apps

### Шаг 2.1. Запуск интеграции с Power Apps

1. Откройте список **«Инциденты»** в SharePoint.

2. В верхнем меню выберите **«Интеграция»** (Integrate) → **«Power Apps»** → **«Настроить формы»** (Customize forms).

3. Откроется Power Apps Studio в браузере. Подождите загрузки интерфейса.

**Пояснение:** SharePoint автоматически создаст базовую форму на основе всех столбцов списка. Наша задача — доработать её для улучшения пользовательского опыта.

### Шаг 2.2. Изучение структуры сгенерированной формы

После загрузки Power Apps Studio вы увидите:

- **FormScreen1** — экран, содержащий форму.
- **SharePointForm1** — элемент управления формы. Свойство **DataSource** уже установлено на список «Инциденты».
- **SharePointIntegration** — скрытый элемент управления, который обеспечивает связь между SharePoint и Power Apps.

Свойства SharePointIntegration:

| Свойство | Формула | Назначение |
|----------|---------|-----------|
| OnNew | `NewForm(SharePointForm1)` | Переключение в режим создания |
| OnView | `ViewForm(SharePointForm1)` | Переключение в режим просмотра |
| OnEdit | `EditForm(SharePointForm1)` | Переключение в режим редактирования |
| OnSave | `SubmitForm(SharePointForm1)` | Сохранение изменений |
| OnCancel | `ResetForm(SharePointForm1)` | Отмена изменений |

### Шаг 2.3. Настройка отображения полей формы

1. Выберите элемент **SharePointForm1** в дереве элементов (левая панель).

2. В правой панели свойств найдите раздел **«Поля»** (Fields).

3. Нажмите **«Изменить поля»** (Edit fields) → **«Добавить поле»** (Add field).

4. Убедитесь, что добавлены все необходимые поля:
   - Название
   - Описание
   - Дата регистрации
   - Статус
   - Ответственный
   - Категория (Lookup)
   - Приоритет (Lookup)

5. Удалите ненужные поля, если они были добавлены автоматически (например, ID, Author, Created).

### Шаг 2.4. Настройка полей Lookup в форме

Поля Lookup в Power Apps отображаются как **Combo Box** (поле со списком). Это позволяет пользователю выбирать значение из выпадающего списка.

1. Выберите карточку поля **«Категория»** в форме.

2. Убедитесь, что элемент управления — **Combo Box**.

3. В правой панели настройте свойства:
   - **Items:** `'Категории инцидентов'` — источник данных для выпадающего списка.
   - **SearchField:** `Title` — поле для поиска.
   - **DisplayFields:** `["Title"]` — отображаемое поле.

4. Аналогично настройте карточку поля **«Приоритет»**:
   - **Items:** `'Приоритеты'`
   - **SearchField:** `Title`
   - **DisplayFields:** `["Title"]`

**Пояснение:** В отличие от стандартной формы SharePoint, где Lookup-поля могут быть ограничены по функциональности, Power Apps позволяет гибко настраивать поведение этих полей, включая фильтрацию, поиск и каскадные зависимости.

### Шаг 2.5. Настройка автоматического заполнения полей

Добавим автоматическое заполнение поля «Дата регистрации» текущей датой при создании нового инцидента.

1. Выберите карточку поля **«Дата регистрации»**.

2. Выберите элемент **DatePicker** внутри карточки.

3. В свойстве **DefaultDate** введите формулу:
   ```
   If(SharePointForm1.Mode = FormMode.New, Today(), ThisItem.'Дата регистрации')
   ```

**Пояснение:** Эта формула проверяет, находится ли форма в режиме создания. Если да — подставляется сегодняшняя дата. Если форма открыта для просмотра или редактирования — отображается сохранённая дата.

### Шаг 2.6. Настройка поля «Ответственный»

1. Выберите карточку поля **«Ответственный»**.

2. Убедитесь, что используется элемент управления **Combo Box** с источником данных `Office365Users` или `Users`.

3. В свойстве **DefaultSelectedItems** можно добавить формулу для автоматической подстановки текущего пользователя:
   ```
   If(SharePointForm1.Mode = FormMode.New, {DisplayName: User().FullName, Claims: "i:0#.f|membership|" & User().Email}, ThisItem.Ответственный)
   ```

### Шаг 2.7. Настройка порядка и компоновки полей

1. Перетащите карточки полей в удобном порядке, например:
   - Название
   - Категория
   - Приоритет
   - Описание
   - Дата регистрации
   - Статус
   - Ответственный

2. Для улучшения внешнего вида можно изменить ширину карточек, выбрав их и перетащив маркеры.

3. Настройте **высоту** карточки «Описание», чтобы отображалось несколько строк текста.

### Шаг 2.8. Настройка кнопок формы

По умолчанию форма содержит кнопки «Сохранить» и «Отмена». Проверим их работу.

1. Выберите кнопку **«Сохранить»** (Save).

2. Убедитесь, что в свойстве **OnSelect** указана формула:
   ```
   SubmitForm(SharePointForm1)
   ```

3. Выберите кнопку **«Отмена»** (Cancel).

4. Свойство **OnSelect**:
   ```
   ResetForm(SharePointForm1)
   ```

### Шаг 2.9. Добавление уведомления об успешном сохранении

1. Выберите **SharePointForm1**.

2. В свойстве **OnSuccess** введите формулу:
   ```
   Notify("Инцидент успешно зарегистрирован", NotificationType.Success);
   ResetForm(SharePointForm1);
   RequestHide()
   ```

**Пояснение:** Функция `Notify` отображает всплывающее уведомление. `RequestHide()` закрывает форму и возвращает пользователя в SharePoint.

### Шаг 2.10. Сохранение и публикация формы

1. Нажмите **«Файл»** (File) → **«Сохранить»** (Save).

2. Нажмите **«Опубликовать»** (Publish) → **«Опубликовать эту версию»** (Publish this version).

3. Вернитесь в SharePoint. Откройте список «Инциденты» и нажмите **«Добавить элемент»**. Убедитесь, что открывается созданная форма Power Apps.

## Часть 3. Проверка работы решения

1. В SharePoint откройте список **«Инциденты»** и нажмите **«Добавить элемент»**.

2. Заполните форму:
   - Название: «Не работает VPN»
   - Категория: «Сеть»
   - Приоритет: «Высокий»
   - Описание: «Пользователь не может подключиться к корпоративной сети через VPN»
   - Ответственный: выберите себя или коллегу
   - Дата регистрации: должна автоматически подставиться текущая дата

3. Нажмите **«Сохранить»**. Убедитесь, что появилось уведомление об успешном сохранении.

4. Проверьте список — новый инцидент должен отображаться.

5. Откройте инцидент для редактирования — форма должна отображать сохранённые значения.

6. Измените статус на «В работе» и сохраните. Убедитесь, что изменения применились.
