# Лабораторная работа: Создание сайта для управления проектами с канбан-доской в SharePoint Online

## Цель работы

Научиться создавать сайт для управления проектами на основе шаблона SharePoint Online, настраивать список задач с необходимыми столбцами и создавать визуальную канбан-доску (Board View) для отслеживания прогресса проектных задач.

## Теоретическая часть

### Что такое сайт для управления проектами

Сайт для управления проектами в SharePoint Online — это готовое решение, предоставляемое Microsoft, которое создаёт централизованный хаб для задач, вех и совместной работы команды. При создании сайта по шаблону «Project management» автоматически создаются предварительно настроенные компоненты: список задач, календарь, библиотека документов и веб-часть сводки по проекту.

### Что такое канбан-доска и Board View в SharePoint

Канбан-доска — это визуальный инструмент управления задачами, где задачи представлены в виде карточек, перемещающихся по колонкам, каждая из которых отражает определённый этап рабочего процесса. В SharePoint Online существует встроенная возможность создания канбан-доски через **Board View** — специальный тип представления списка, который отображает элементы списка в виде карточек, организованных в вертикальные колонки (называемые «корзинами» или bucket).

Board View был представлен в январе 2022 года и доступен как в списках SharePoint Online, так и в Microsoft Lists. Он особенно полезен для отслеживания рабочих процессов, этапов проектов, одобрений и статусов задач.

### Ключевое ограничение Board View

Для создания Board View в списке должен быть хотя бы один столбец типа **«Выбор»** (Choice) или **«Да/Нет»** (Yes/No). Только эти типы столбцов могут использоваться для организации доски по корзинам. Текстовые, числовые, даты и столбцы типа «Человек» не поддерживаются для группировки карточек.

### Преимущества канбан-доски в SharePoint

Использование канбан-доски в SharePoint даёт команде несколько преимуществ:
- **Прозрачность процесса** — все участники видят текущий статус задач и могут отслеживать прогресс проекта в реальном времени.
- **Визуальный контроль** — задачи отображаются наглядно, что помогает выявлять узкие места и дисбаланс нагрузки.
- **Повышение вовлечённости команды** — каждый видит, как его вклад влияет на общий результат.
- **Гибкость управления** — добавление новых задач, изменение приоритетов и корректировка этапов рабочего процесса просты и интуитивны.

## Архитектура решения

В данной лабораторной работе мы создадим:

| Компонент | Назначение |
|-----------|-----------|
| **Сайт «Управление проектами»** | Централизованный хаб для проектных данных и совместной работы |
| **Список «Задачи проекта»** | Основной список для хранения всех проектных задач |
| **Board View (Канбан-доска)** | Визуальное представление задач, сгруппированных по статусу |
| **Календарь проекта** | Представление задач с датами для планирования сроков |
| **Библиотека документов** | Хранилище проектных артефактов |

Логика связи: задачи из списка «Задачи проекта» отображаются на канбан-доске в виде карточек, сгруппированных по столбцу «Статус». При перемещении карточки между колонками статус задачи автоматически обновляется.

## Часть 1. Создание сайта для управления проектами

### Шаг 1.1. Переход к созданию сайта

1. Войдите в Microsoft 365 и откройте приложение **SharePoint** через панель запуска приложений (app launcher).

2. На стартовой странице SharePoint нажмите **«Создать сайт»** (Create site).

### Шаг 1.2. Выбор шаблона

1. В галерее шаблонов выберите **«Project management»** (Управление проектами). Этот шаблон предоставляет готовую структуру с предварительно настроенными компонентами.

2. Заполните данные сайта:
   - **Название сайта:** `Управление проектами`
   - **Описание:** `Сайт для управления проектами команды`
   - **Политика конфиденциальности:** выберите «Частный» (Private), если сайт предназначен только для участников команды, или «Общедоступный» (Public), если он должен быть доступен всем в организации.

3. Нажмите **«Далее»** (Next).

4. При необходимости добавьте участников и назначьте владельцев сайта. Нажмите **«Готово»** (Finish).

**Пояснение:** SharePoint предоставит сайт в течение нескольких секунд. В отличие от классического шаблона Team Site, шаблон Project management сразу включает в себя список задач, календарь, библиотеку документов и веб-часть сводки по проекту.

### Шаг 1.3. Изучение компонентов сайта

После создания сайта вы увидите главную страницу с несколькими готовыми веб-частями:

| Компонент | Назначение |
|-----------|-----------|
| **Сводка по проекту** (Project Summary) | Отображает ключевые метрики и статусы задач |
| **Список задач** (Tasks) | Основной список для хранения проектных задач |
| **Календарь** (Calendar) | Визуализация задач с датами |
| **Объявления** (Announcements) | Лента новостей проекта |
| **Библиотека документов** (Documents) | Хранилище проектных артефактов |

### Шаг 1.4. Настройка навигации

1. Нажмите **«Изменить»** (Edit) в правом верхнем углу страницы.

2. В меню навигации (левая панель) перетащите ссылки в удобном порядке или скройте ненужные элементы.

3. При необходимости добавьте новые ссылки: нажмите **«Добавить ссылку»** (Add link) и укажите название и URL.

4. Сохраните изменения.

## Часть 2. Настройка списка задач проекта

### Шаг 2.1. Открытие списка задач

1. Перейдите в **«Содержимое сайта»** (Site Contents).

2. Нажмите на список **«Задачи»** (Tasks), чтобы открыть его.

### Шаг 2.2. Добавление необходимых столбцов

Стандартный список задач уже содержит несколько столбцов, но для полноценного управления проектом добавим дополнительные.

**Добавление столбца «Приоритет»:**

1. Нажмите **«+ Добавить столбец»** (+ Add column).

2. Выберите тип **«Выбор»** (Choice).

3. Введите имя: `Приоритет`.

4. Добавьте варианты:
   - `Низкий`
   - `Средний`
   - `Высокий`
   - `Критический`

5. В разделе «Значение по умолчанию» выберите `Средний`.

6. Нажмите **«Сохранить»** (Save).

**Добавление столбца «Статус» (если его нет):**

1. Нажмите **«+ Добавить столбец»** → **«Выбор»**.

2. Имя: `Статус`.

3. Варианты:
   - `Не начато`
   - `В работе`
   - `На проверке`
   - `Завершено`

4. Значение по умолчанию: `Не начато`.

5. Нажмите **«Сохранить»**.

**Добавление столбца «Исполнитель»:**

1. Нажмите **«+ Добавить столбец»** → **«Человек»** (Person).

2. Имя: `Исполнитель`.

3. Разрешите выбор: «Люди и группы» (People and Groups).

4. Нажмите **«Сохранить»**.

**Добавление столбца «Срок»:**

1. Нажмите **«+ Добавить столбец»** → **«Дата и время»** (Date and time).

2. Имя: `Срок`.

3. Формат: «Только дата» (Date only).

4. Нажмите **«Сохранить»**.

**Добавление столбца «Оценка трудозатрат»:**

1. Нажмите **«+ Добавить столбец»** → **«Число»** (Number).

2. Имя: `Оценка трудозатрат (ч)`.

3. Количество десятичных знаков: 1.

4. Нажмите **«Сохранить»**.

### Шаг 2.3. Проверка структуры списка

Убедитесь, что список «Задачи» содержит следующие столбцы:

| Имя столбца | Тип | Назначение |
|-------------|-----|-----------|
| Название | Однострочный текст | Краткое описание задачи |
| Статус | Выбор | Этап выполнения задачи |
| Приоритет | Выбор | Важность задачи |
| Исполнитель | Человек | Ответственный за задачу |
| Срок | Дата | Дедлайн задачи |
| Оценка трудозатрат (ч) | Число | Планируемое время на выполнение |
| Описание | Многострочный текст | Детальное описание задачи |

## Часть 3. Создание канбан-доски (Board View)

### Шаг 3.1. Переход к созданию представления

1. Откройте список **«Задачи»**.

2. В правом верхнем углу нажмите на выпадающее меню текущего представления (обычно **«Все элементы»** / All Items).

3. Выберите **«Создать новое представление»** (Create new view).

### Шаг 3.2. Настройка параметров Board View

В открывшейся панели справа заполните параметры:

1. **Имя представления** (View name): `Канбан-доска` или `Status Board`.

2. **Показать как** (Show as): выберите **«Доска»** (Board).

3. **Упорядочить доску по** (Organize board by): выберите столбец **«Статус»**.

4. **Сделать это представлением по умолчанию** (Make this a public view): отметьте, если хотите, чтобы все пользователи с доступом к списку видели эту доску.

5. Нажмите **«Создать»** (Create).

**Пояснение:** SharePoint автоматически создаст Board View и добавит его в список представлений. Теперь задачи будут отображаться в виде карточек, сгруппированных по столбцам «Не начато», «В работе», «На проверке» и «Завершено».

### Шаг 3.3. Настройка карточек на доске

1. На канбан-доске нажмите **«Настроить карточку»** (Customize card) — обычно эта опция доступна в меню доски или через настройки представления.

2. Выберите поля, которые должны отображаться на карточке:
   - `Название` (обязательно)
   - `Исполнитель`
   - `Срок`
   - `Приоритет`
   - `Оценка трудозатрат (ч)`

3. Нажмите **«Сохранить»**.

**Важно:** В Board View можно отобразить не более 6 полей на карточке. Если вы попытаетесь добавить больше, лишние поля не будут отображаться.

### Шаг 3.4. Настройка условного форматирования карточек

1. В режиме настройки карточки найдите раздел **«Условное форматирование»** (Conditional formatting).

2. Добавьте правило: если `Срок` меньше сегодняшней даты и `Статус` не равен «Завершено», выделить карточку красным цветом.

3. Это позволит визуально выделять просроченные задачи прямо на доске.

### Шаг 3.5. Использование канбан-доски

1. **Перемещение задач:** просто перетащите карточку из одной колонки в другую. При этом значение столбца «Статус» автоматически обновится.

2. **Добавление задачи:** нажмите **«+ Добавить»** (+ Add) в нужной колонке — новая задача сразу получит соответствующий статус.

3. **Фильтрация:** используйте панель фильтров для отображения задач только по определённому исполнителю или приоритету.

4. **Сортировка:** настройте сортировку карточек внутри колонки по сроку или приоритету.

## Часть 4. Дополнительные представления списка

### Шаг 4.1. Создание представления «Мои задачи»

1. Откройте список **«Задачи»**.

2. Нажмите **«Все элементы»** → **«Создать новое представление»**.

3. Выберите тип **«Список»** (List).

4. Имя: `Мои задачи`.

5. В разделе **«Фильтр»** (Filter) добавьте условие: `Исполнитель` равно `[Я]` (или `[Me]`).

6. Нажмите **«Создать»**.

**Пояснение:** Это представление позволит каждому участнику видеть только свои задачи, что особенно полезно в больших командах.

### Шаг 4.2. Создание представления «Просроченные задачи»

1. Создайте новое представление типа **«Список»**.

2. Имя: `Просроченные`.

3. Фильтр: `Срок` меньше `[Сегодня]` И `Статус` не равно `Завершено`.

4. Нажмите **«Создать»**.

### Шаг 4.3. Создание представления «Календарь»

1. Создайте новое представление типа **«Календарь»** (Calendar).

2. Имя: `Календарь проекта`.

3. В настройках календаря укажите:
   - Начало: `Срок`
   - Конец: `Срок` (или создайте отдельный столбец «Дата окончания»)

4. Нажмите **«Создать»**.

**Пояснение:** Календарное представление позволяет визуально оценить распределение задач по срокам и выявить перегрузки.

## Часть 5. Настройка библиотеки документов

### Шаг 5.1. Создание структуры папок

1. Перейдите в **«Содержимое сайта»** → **«Документы»** (Documents).

2. Создайте папки для организации проектных артефактов:
   - `01_Устав проекта`
   - `02_Требования`
   - `03_Дизайн`
   - `04_Тестирование`
   - `05_Отчёты`

3. Для создания папки нажмите **«+ Создать»** → **«Папка»** и введите имя.

### Шаг 5.2. Добавление метаданных

1. Для каждого документа можно добавить метаданные (например, «Версия», «Статус документа», «Автор»).

2. Щелкните правой кнопкой мыши по столбцу в библиотеке → **«Создать столбец»** → выберите тип и настройте.
